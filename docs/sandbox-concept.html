ETechnical blueprint

Security, privacy and cost controls

A public link with our API key behind it needs several layers. Each one below is implemented and covered by tests.

Links are secrets
  • Invite link = readable prefix + 8 random characters (about 40 bits). Custom codes need 12+ characters.
  • Report link = 16 random characters (about 80 bits), private until published.
  • “New link” rotates the token and the old one stops working at once. Links expire after 30 days by default.
  • Referrer-Policy: no-referrer, so tokens never leak to other sites.
Abuse limits
  • 240 sandbox requests per minute per IP
  • 20 runs per minute per IP, 60 runs per 10 minutes per sandbox
  • 30 uploads and 10 contact forms per 10 minutes
  • Admin: 10 failed sign-ins lock the IP for 15 minutes; constant-time token comparison
Hard cost ceiling
  • Credits are deducted on the server before a run and refunded on failure.
  • A run is refused when it would likely cross the sandbox’s USD budget.
  • USD never reaches prospect pages or reports, only a “trial used up” flag.
  • npm run real-check measures the real cost of every agent before launch.
Data and content
  • Synthetic data only before signing; generated names are fictional.
  • HTML made by the agent runs in a sandboxed iframe with CSP default-src 'none'.
  • Model output is rendered by our own Markdown renderer, never as raw HTML.
  • No automated decisions about people (Decree 13, Law 91/2025): a person approves.
